# PadInk 开发者指南

从 `https://github.com/double-u-zw/PadInk` 克隆源码；下文在仓库根目录执行。本指南包括源码安装、签名续期、自动检查、回放和 UI 检查。普通安装见 [使用者安装指南](使用者安装指南.md)，发行见 [RELEASE](RELEASE.md)。

## 获取源码与公开范围

```sh
git clone https://github.com/double-u-zw/PadInk.git
cd PadInk
git checkout v0.3.0-beta.2
./engineering/scripts/build-and-test.sh
```

当前验证工具链为 Xcode 27 / Swift 6.4。测试与无签名构建不需要维护者的团队配置；源码安装时运行“首次设置 PadInk.command”，用自己的 Xcode 账号与设备生成本机签名配置。免费账户能力和侧载名额按 Apple / AltStore 实际提示处理。

公开内容包括 Apps、Sources、Hosts、Config 模板、Xcode 工程、SwiftPM、Tests、已脱敏的 Fixtures、engineering 工具和 docs；采用根目录 MIT LICENSE。本机签名配置、证书、凭据、设备备份、诊断、构建缓存和未经检查的旧开发历史不公开。Beta 2 tag 对应经检查的当前源码快照；Beta 1 tag 仍是当时的文档发布。

## 版本身份与芯片选择

本机源码构建和内部自用的开发版叫 `PadInk Dev`；对外发布的正式版统一叫 `PadInk`，包括当前 Beta 2。Beta/RC 是发布阶段，不是额外的安装版别。公开下载不提供 PadInk Dev。内部双端测试须用同一版。两版独立 bundle ID、设置、Keychain 配对、USB 端口与 Bonjour 发现，首次开发版不继承原有授权/配对。Xcode 和 `engineering/commands/更新 PadInk.command` 默认开发版，开发安装不会覆盖 `/Applications/PadInk.app`。更新命令默认为开发版生成 AltStore IPA，双端 Xcode 安装需显式选择 `PADINK_IPAD_INSTALLER=xcode`。

```sh
PADINK_BUILD_VARIANT=development ./engineering/scripts/build-and-test.sh
python3 engineering/scripts/package-altstore.py --variant development --out build/share/candidates/0.3.0-b7-dev.1
python3 engineering/scripts/package-altstore.py --variant release --out build/share/candidates/0.3.0-b7-trial.1
```

统一检查默认正式版身份的无签名架构覆盖构建；打包脚本实际分别编译 arm64 / x86_64 并核对每个二进制和 dSYM。Apple M 系列用 arm64，Intel 用 x86_64；iPad 共用各自身份的 arm64 IPA，不按 Mac 芯片另分。先不要用新开发版替换旧正式版。确需维护旧源码安装身份时显式运行 `PADINK_BUILD_VARIANT=release zsh 'engineering/commands/更新 PadInk.command'`；它会安装双端，应按实际任务授权执行。

内部验收另检查两版可同时保留，开发安装不覆盖 PadInk；首次开发版独立授权、配对，设置互不影响。这些是开发者检查项，不是公开包使用者的安装选择。

## 开发版的日常使用与 AltStore 续签

当前日常开发使用 **PadInk Dev 0.3.0 / build 8**：Mac 保持现有开发签名与安装身份，iPad 由官方 AltStore Classic 管理安装、更新和续签。两端仍使用同一开发版的 USB / Bonjour / 配对命名空间；首次迁移后的 iPad 需要重新与 Mac 配对。

运行 `zsh 'engineering/commands/更新 PadInk.command'` 默认更新 Mac PadInk Dev，并生成、在 Finder 显示 `PadInk-Dev-AltStore.ipa`。将 IPA 传到 iPad，在 **AltStore → My Apps → +** 导入；脚本不会用 Xcode 覆盖 AltStore 的 iPad 安装，也不会把 IPA 生成成功写成双端安装成功。新代码必须重新导入 IPA，Refresh All 只续签 AltStore 缓存的当前版本。

在 **AltStore → Settings** 启用 **Background Refresh**，iPad 系统的后台 App 刷新也须允许 AltStore；Mac AltServer 保持运行并设为登录时打开。先在 My Apps 用 **Refresh All** 验证能够续签，再恢复 PadInk Dev 使用。后台刷新由 iPadOS 调度，Mac / AltServer 必须可达，不能保证固定时刻成功；以实际到期时间和刷新结果为准。[官方续签说明](https://faq.altstore.io/altstore-classic/your-altstore)

### 从本轮 Xcode iPad 开发版切换

已安装的 Xcode iPad 开发版身份为 `dev.padink03.<原团队>.ipad.development`；AltStore IPA 原始身份为 `dev.padink.altstore.ipad.development`，AltStore 重签后会追加团队后缀。它们是不同的安装身份。Xcode 安装不会自动进入 AltStore 的 My Apps，也不能靠开启 Background Refresh 接管。

迁移前先准备新 IPA，保留旧签名 App、源码身份及必要设置恢复材料；确认正在使用的文稿已保存。免费账户同时侧载名额含 AltStore，若 AltStore、正式版 PadInk 与 Xcode PadInk Dev 已占满三个名额，须先腾出旧 Xcode PadInk Dev 的名额。只处理旧 **iPad PadInk Dev**，保留现有正式版 PadInk 和 AltStore；移除旧 App 会删除其 App 容器设置，新 AltStore 身份须重新设置与配对。没有确认备份或身份时不要自动卸载。此次迁移完成后，更新和续签保持同一 AltStore 身份、同一 Apple ID，保留 App，不再重复卸载。

Mac 继续安装到 `/Applications/PadInk Dev.app`，不使用 AltStore 测试包的 Mac DMG 替换本机开发签名。必须保留 `Config/Signing.local.xcconfig`。仅在明确选择 Xcode 开发安装时用 `PADINK_IPAD_INSTALLER=xcode zsh 'engineering/commands/更新 PadInk.command'`；切换到 AltStore 后，日常更新用默认命令。

实际使用可逐项验证：在测试文稿写擦、滚动和缩放，保存后重开；连续使用 30–60 分钟；抬笔后拔插 USB、切后台再恢复；下次覆盖更新确认设置与配对保留。结果填写[真人清单](试用验收清单.txt)，注明 PadInk Dev、双端 build/source、目标应用与日期；只填写实际完成的项目。开发版体验结果可以支持源码验收，正式包安装、签名、公证及 TestFlight 仍要用发布包再验证。

## 1. 日常开发与构建

在工程根目录执行：

```sh
./engineering/scripts/build-and-test.sh
```

它运行完整 Swift suite、Python checks、Release 诊断/源码身份检查、一致性工程生成、Mac 架构覆盖与 iPad 无签名 Release build，以及版本、privacy、图标和 dSYM UUID 核对。输出默认 `build/check/`；`PADINK_BUILD_ROOT` 可指定本地输出，`PADINK_BUILD_CONFIGURATION=Debug` 可检查 Debug host；冻结候选的无签名构建可设置 `PADINK_BUILD_CHANNEL=rc`。通过自动检查不代表真人体验或 Apple 分发通过。

单项开发检查：

```sh
swift test --scratch-path build/dev/spm
swift test --scratch-path build/dev/spm --filter 'ReplayKitTests|BaselineEvidenceTests|InkPlacementTests'
python3 engineering/scripts/build-identity.py --json
```

`PadInk.xcodeproj`、host Info.plist 与 entitlements 由 `python3 engineering/scripts/generate-project.py` 确定性生成；需要更改工程时先改 generator / Config，再生成并核对。不要手改生成文件作为唯一配置。产品模块与安全边界见 [ARCHITECTURE](ARCHITECTURE.md)，帧/payload 改动同步 [PROTOCOL](PROTOCOL.md)、MessageRegistry 和 golden 测试。

`Fixtures/replay/baseline-real-strokes.json` 包含真实捕获的 85 笔 / 7143 点；保留来源提交和样本摘要，已去除本机路径及原始诊断标识。`Fixtures/replay/persistence/` 的六份 PPTX 是 Git 跟踪的持久化/位置回归，分为 baseline-0.1、replay-hid、replay-private 三组 before/after-reopen。测试读取 repo-relative 文件并校验 `manifest.json` 中的 SHA，不再依赖旧桌面 build；必须实际执行，不能以文件不存在 skip 当通过。fixture manifest 保留来源提交与测试用途；Office 作者元数据已去除，InkML、slide 和关系内容保持原样。

`build/` 和 `.build/` 是 ignored 本地输出，随时可重建。只有不可替代原始样本和当前安装恢复所需的包、匹配 dSYM 与源码身份进入统一 archives；报告、重复日志和截图不长期保存。

## 2. 回放与源码包

`padink-replay` 是本机工具，不进入 App。inspect / persistence 只读指定测试文件：

```sh
swift run --scratch-path build/dev/spm padink-replay inspect <测试文件.pptx>
swift run --scratch-path build/dev/spm padink-replay persistence <保存前.pptx> <重开后.pptx>
```

真实 PowerPoint / Preview 回放会投递输入并接管指针，须在明确授权、无人使用 Mac 时执行。工具创建测试文稿，保存、关闭、重开并生成本地 evidence；运行终端需要辅助功能/事件投递权限。

```sh
swift run --scratch-path build/dev/spm padink-replay powerpoint \
  --fixture Fixtures/replay/baseline-real-strokes.json \
  --event-source hid --strokes 85 --out build/evidence/replay-local
```

先核对命令和输出目录；`--dry-run` 只检查/准备流程，不是应用持久化证据。紧急停止可按 Ctrl-C、切换到其他前台应用，或创建程序打印的 STOP 文件。每条退出路径释放 pen / proximity。`--event-source private` 仅用于明确的 A/B 调查，产品默认仍是 hid。本次 shape / InkML 输出用于临时复核，不把生成成功当验收；长期仅保留 Fixtures 尚未覆盖的不可替代原始样本，不保留历史报告或复核叙事。

```sh
./engineering/commands/打包源码.sh
python3 engineering/scripts/package-source.py <明确commit>
python3 engineering/scripts/rc-release.py prepare --preview --out build/rc/preview
python3 engineering/scripts/rc-release.py check build/rc/preview
```

普通源码包绑定所选 Git commit，不包含未提交 diff、签名配置或 evidence；历史包可能有旧指南文件名。RC preview 显式标记 working-tree/unsigned，不是用户可安装发行。正式 prepare、签名、公证与分发见 RELEASE。

## AltStore IPA 构建

```sh
python3 engineering/scripts/build-altstore-ipa.py
```

输出为 `build/altstore/PadInk-AltStore.ipa`（正式版身份）；`--variant development` 输出 `PadInk-Dev-AltStore.ipa` 和版本/源码摘要 `PadInk-Dev-AltStore.json`。维护者构建需要 Xcode，使用者安装不需要。脚本使用独立 `dev.padink.altstore.ipad`，无签名编译，打包标准 Payload；不读取 Apple ID 凭据、不注册 App ID、不安装到设备，也不修改 `Config/Signing.local.xcconfig`。认证、签名和刷新全部交给官方 AltServer / AltStore Classic。

给其他人试用时运行 `python3 engineering/scripts/package-altstore.py`。输出默认在 `build/share/release/`：匹配源码与版本的 对应单架构 Mac DMG、IPA、安装说明、真人验收清单、文档快照和 SHA256 校验组成测试版 ZIP；双端显式使用 `rc` 渠道与 `altstore` 分发，本机开发默认不变。另行下载并核验官方 AltServer 1.8.1（98）原包。Mac 测试包固定使用 `dev.padink.altstore.mac`，ad-hoc 签名，不依赖本机个人开发证书；尚无 Developer ID 公证，首次打开需用户按系统提示确认，后续更新不保证 TCC / Keychain 授权无缝延续。脚本只构建和打包，不安装、签 Apple 账号、覆盖现有 App 或发布远端 Release。

当前源码为 0.3.0 / build 9（Beta 2），本机已安装开发版仍为 build 8；尚未冻结新的正式 RC；另行准备的 AltStore 受邀试用包清单保留未发布与未真人验收状态；已有输出不会被脚本覆盖。可用 `--out build/share/candidates/0.3.0-b7-trial.1` 为候选建立独立目录。构建源码摘要不包含文档，包内文档另由 SHA256SUMS 核对。源码未提交时用 `rc-release.py prepare --preview` 私下保存准确快照，并保存双端匹配 dSYM；不要把工作区包写成干净提交的正式 RC。

继续开发时修改源码，交付新版本前递增 `Config/Version.xcconfig` 的 build 号，再运行同一脚本；先运行 `./engineering/scripts/build-and-test.sh`，并对新包验证实际更新。不要在普通续签时替换 IPA 内容，Refresh All 续签的是 AltStore 已缓存的当前版本。测试分发包不代替下文的正式 Developer ID 公证发布流程。

首次 AltServer 安装须先避免撤销正式安装使用的证书；检查步骤见[安装指南](使用者安装指南.md)。不要用正式 Bundle ID 替换此包的独立身份。开发版显示名 PadInk Dev、正式版 PadInk，安装时按包内身份选择。现有 `engineering/commands/首次设置 PadInk.command`、`engineering/commands/更新 PadInk.command` 与 `engineering/scripts/lib/` 保留，用于当前 Xcode 开发安装的身份延续；RC、TestFlight 与 Mac 公证工具继续保留。

## 3. 可选的 Xcode 双端安装与免费签名续期

本节仅适用于显式选择 `PADINK_IPAD_INSTALLER=xcode` 的双端 Xcode 安装；日常 AltStore 开发版按前文操作。Personal Team 用于开发测试；同一个完整源码目录、Apple ID 与本机签名配置必须延续。第二 Apple ID / 第二套设备从零安装尚未验收；脚本测试不代替其实际操作理解。

### 1. 先准备这些东西

- Mac、iPad、Apple Pencil，以及一根能传数据的 USB 线。日常可用 Wi-Fi，但首次安装和免费签名续期要插线。
- 你自己的 Apple ID，免费账户即可；不要使用开发者的账号或团队 ID。
- Mac 上的完整 **Xcode**（不是仅命令行工具），版本要支持你的 iPadOS。首次下载安装和两端编译需要一些时间及可用空间。
- 收到的完整 PadInk 文件夹。先解压到你能保留和写入的位置，例如“文稿”；不要只拿出两个 `.command` 文件，也不要直接在 ZIP 里运行。每周续期继续使用同一个文件夹和 Apple ID。

两端分工：Mac 运行 PadInk 菜单栏应用、授权并打开要操作的文稿；iPad 运行 PadInk、保持前台、确认配对并操作画面。Mac 不需要打开 PadInk 主窗口。

### 2. 首次安装：在 Mac 做

1. 从 App Store 安装 Xcode，打开一次，完成许可与组件安装。在 **Xcode › 设置 › 账户** 登录自己的 Apple ID，等待 **Personal Team** 显示。若脚本仍找不到 Xcode，在 **Xcode › 设置 › 位置** 把命令行工具选为完整 Xcode。
2. 用 USB 连接 iPad，解锁并点 **“信任此电脑”**。在 Xcode 的 **Window › Devices and Simulators** 中选中 iPad，等待设备准备完成。
3. 在 iPad **设置 › 隐私与安全性 › 开发者模式** 中打开开关，按提示重启，再解锁确认启用。若看不到此选项，先完成上一步与 Xcode 的连接后再看。Apple 的 [开发者模式说明](https://developer.apple.com/documentation/xcode/enabling-developer-mode-on-a-device) 可供核对。
4. 在源码的 `engineering/commands/` 中双击 **“首次设置 PadInk.command”**。单个团队会自动使用；如果列出多个团队，选择自己的 Personal Team。已有本机签名配置会保留，防止续期变成另一个 App。
5. 保持 iPad 插线、解锁，在工程根目录运行 `PADINK_IPAD_INSTALLER=xcode zsh 'engineering/commands/更新 PadInk.command'`，等待六个步骤完成。它从同一份源码构建和安装 Mac 与 iPad，并显示本次构建标识、iPad 签名有效期和下一步。
6. iPad 若提示 **“开发者不受信任”**，去 **设置 › 通用 › VPN 与设备管理**，点自己的 Apple ID 并信任，然后打开 iPad 上的 **PadInk Dev**。不需要仅为信任开发者重新编译。

若双击 `.command` 被 macOS 阻止，确认文件来自你信任的 PadInk 提供者后，尝试右键文件 › 打开；仍被阻止时在系统设置的“隐私与安全性”中查看这次阻止提示。不要关闭整个系统的安全检查。

安装脚本会打开 Mac 应用，并尝试打开 iPad 应用；未能自动打开时会给出手动步骤。默认安装到 `/Applications/PadInk Dev.app`，iPad 同样为 PadInk Dev；显式选 release 时才安装正式版身份。权限不足时保留已有 App 并停止，请先核对安装权限。新包复制、验签和启动后，旧显示名 App 与回滚副本仍保留；检查设置、已配对设备和实际连接保持，再确认清理。

### 3. 首次运行：两端各做什么

| Mac | iPad |
|---|---|
| 打开 **PadInk Dev**，点击菜单栏笔形图标。首次使用引导说明两端步骤。 | 打开 **PadInk Dev**，保持 App 在前台、屏幕解锁。 |
| 在 PadInk 中打开系统设置，允许 **屏幕录制**（显示画面）和 **辅助功能**（书写、点击、滚动）。按系统提示重新打开 PadInk。 | 保持 USB 插线，首次在 iPad 点 **允许配对**。 |
| 首次在 Mac 也点 **允许配对**。只确认自己正在连接的设备。 | 等右上角显示 **USB** 和画面状态，再看到 Mac 画面。 |
| 打开要操作的文稿，选择应用自己的笔或标注工具。 | 用 Pencil 书写；手指点击选工具，双指滚动或捏合。 |

录屏允许但仍无画面时，先按系统要求彻底退出、重新打开 Mac PadInk；仅关闭菜单不是退出。辅助功能缺失时即使画面显示正常，输入也可能不工作。PowerPoint 缩放首次可能另询问 **自动化** 权限，允许 PadInk 控制 PowerPoint；拒绝时到 **系统设置 › 隐私与安全性 › 自动化** 调整，Pencil 书写无需此项权限。

确认已经能看到画面后，先完成一个小任务：在 PowerPoint **绘图 › 笔** 或 GoodNotes 的笔工具里写两笔，保存文稿，再确认应用内结果。PadInk 不替你保存文稿，也没有独立的 iPad 笔记本。

### 4. 连接状态与 Wi-Fi

Mac 菜单栏面板和 iPad 右上角都会显示当前状态、USB/Wi-Fi 及恢复提示。iPad 右上角齿轮打开 **设置**。连接已经建立和画面可以操作是两个步骤；看到“等待画面”时先看 Mac 的录屏提示，不要反复配对。

- **第一次推荐 USB 配对**。以后打开两端即可自动连接。两端在同一局域网，并允许系统询问的 **本地网络** 权限后，已配对设备也可使用 Wi-Fi。
- **不插线配对 Wi-Fi**：在 iPad 的 **设置 › 连接与设备** 点 **配对 Wi-Fi**；Mac 打开 **设置 › Wi-Fi 连接**，在你的 iPad 旁点 **配对**。核对两端六位短码，完全一致才在两端允许。配对窗口约 120 秒，过期可重开。
- **插 USB 自动切到 USB，拔线自动尝试恢复 Wi-Fi**。当前正在进行的书写/手势会先安全结束，切换恢复后请重新落笔；不要期待断线期间的笔迹被补送。
- Wi-Fi 找不到或连不上：确认两端同一网络、本地网络权限已允许、iPad 在前台。公司/课堂/访客网络可能禁止设备互连；此时优先用 USB，不必重复忘记设备。
- **恢复中**：保持 iPad 前台并检查数据线/网络；持续不恢复时重新打开两端。主动点过“暂停连接”时，需在 Mac 点 **重新连接**。

只有需要更换可信设备或明确修复配对失败时才用“忘记设备”。Mac 在 **设置 › 已配对设备**、iPad 在 **设置 › 连接与设备 › 已配对的 Mac** 里管理设备，都会要求确认；忘记后，在 iPad 同页点 **允许重新配对**，Mac 点 **重新连接**，再在两端确认。普通断线、续期和无画面无需忘记设备。

### 5. 应用与输入设置

- **PowerPoint**：在 Mac 应用的“绘图”里选笔后书写，文件由 PowerPoint 保存。捏合调用公开的视图缩放；不可用时用应用自己的比例控件。
- **GoodNotes for Mac**：在已打开的文稿内容区书写、普通双指滚动与连续捏合。笔、颜色、橡皮由手指点应用自己的工具栏；编辑文字、打开菜单或弹窗时先回到文稿再缩放。
- **Preview**：使用 PDF 自带的标注工具；完整笔迹、保存重开与滚动/缩放仍需在你的实际 PDF 上确认。
- **Safari、Chrome**：浏览、点击、滚动、页面缩放。不会自动把网页变成可保存的手写笔记。
- iPad **设置 › 允许手指操作 Mac** 开启时可点击、拖动、双指滚动和捏合；关闭后仅 Pencil 操作 Mac。Pencil 优先于手指，避免把落掌误当成另一个动作。

缩放是否可用取决于当前应用、文稿焦点和应用公开的接口。菜单提示不可用时先回到文稿，仍不支持则使用应用自己的缩放控件。**“恢复应用默认缩放”也只在应用公开路径支持时可用**，不保证所有应用都可重置为 100%。详细范围见 [支持矩阵](SUPPORT_MATRIX.md)。

### 6. 每周续期与版本核对

**插线 → 解锁 iPad → 在原源码目录运行 `PADINK_IPAD_INSTALLER=xcode zsh 'engineering/commands/更新 PadInk.command'` → 等显示“两端安装完成” → 打开两端。**

免费 Personal Team 的设备安装配置文件在签发后 7 天过期，见 [Apple 账户说明](https://developer.apple.com/help/account/basics/about-your-developer-account)。iPad 应用无法打开也不要删除它，使用原团队覆盖安装。更换团队、丢失本机签名配置或删除 App 可能改变身份/配对，不能当作正常续期步骤。

- iPad **设置 › 关于 PadInk** 的“安装与更新”区可查看到期提醒；Mac 连接到 iPad 后也会显示临近到期提醒。到期前 3 天开始提醒，不代表后台已经续期。
- 更新脚本显示本次安装包的实际签名有效期；不要仅凭“安装完成”认为已经额外延长 7 天。如果临近到期更新仍显示原期限，到期后再覆盖更新，并保留安装日志供排查。
- Mac **关于 PadInk**、iPad **设置 › 关于 PadInk** 可查本机版本与构建；iPad 同页、Mac **诊断** 可查对端版本。只更新一端可能无法连接，恢复时请用同一份源码安装两端。
- 换新的源码包时保留自己的 `Config/Signing.local.xcconfig`，将它放到新包的同一目录再更新；不要复制另一位使用者的签名配置。每周续期无需重新“首次设置”。
- iPadOS 升级后若脚本提示 Xcode 不支持，先更新 Xcode。无法继续安装时保留 iPad App 和原源码文件夹。

### 7. 出问题时：最短恢复与诊断

| 看到的问题 | 下一步 |
|---|---|
| Mac 没有菜单栏图标 | 打开已安装的 PadInk；脚本结束时给出的路径是实际安装位置。 |
| 等待连接 / 没有检测到 iPad | 两端都打开；USB 检查数据线、解锁与“信任此电脑”；Wi-Fi 检查前台、同一网络与本地网络权限。 |
| 已连接但等待画面 / 录屏失败 | 看 Mac 屏幕录制权限提示，授权后按系统要求退出重开 Mac PadInk。持续失败时导出两端诊断。 |
| 画面正常但无法书写/点击 | 检查 Mac 辅助功能权限、文稿是否激活及应用自己的笔工具。仅手指无效时检查“允许手指操作 Mac”。 |
| 配对未完成 / 短码不一致 | 不确认不一致的短码；重新开启 Wi-Fi 配对并核对两端。此前主动断开时在 Mac 点“重新连接”。 |
| 画面恢复中 / 解码失败 | 保持 iPad 前台并等待恢复；持续失败时先导出诊断，再重新打开两端。 |
| 免费签名过期 / iPad App 打不开 | 插线、解锁，用原文件夹与 Apple ID 运行“更新 PadInk”；保留 iPad App。 |
| 免费测试 App 数量已满 | 删除一个不用的测试 App，保留 PadInk。若提示 **App ID 注册额度** 已满，删除 App 不会立即释放该额度，需等 Apple 额度周期重置。 |
| Mac/iPad 签名失败 | Xcode › 设置 › 账户，确认原 Apple ID 仍已登录并处理账户提示。不要换团队重试。 |

**应用已经打开时，先在两端各导出一次诊断：**

1. Mac 打开 PadInk 主窗口的 **诊断**，点 **导出并在 Finder 显示**。文件在 **文稿 / PadInk 诊断**，Finder 会选中新文件。
2. iPad 打开 **设置 › 诊断**，点 **生成 iPad 诊断**，生成后点 **分享诊断文件**，保存到“文件”或通过 AirDrop 传到 Mac。
3. 求助时提供两个 JSON 文件，补一句 **哪个应用、USB 还是 Wi-Fi、最后做了什么、发生时间**。界面内可同时找到两端构建；对端未连接时分别记录本机版本。

应用诊断不含截图、窗口标题、文档名或完整文件路径，只在本机生成，分享由你决定。安装失败时脚本会另给一个 `build/update/<时间>.zip` 安装诊断包；安装日志可能包含本机路径与签名账户信息，发送前可先查看。不要发送 `Config/Signing.local.xcconfig`、钥匙串或证书。

### 8. 有条件时的独立安装验收

有另一套设备时，在自己的 Mac/Apple ID 上照本指南独立完成源码安装，然后只做这些事，约 10–15 分钟（不含 Xcode 下载与首次编译；签名到期续期另做下一阶段验收）：

1. 两端冷启动，USB 首次配对并授权；确认两端版本可找到、等待画面与实际可操作状态能理解。
2. 在一个真实 PowerPoint 或 GoodNotes 文稿里写两笔、保存；滚动并捏合一次。
3. 已配对 Wi-Fi 连上后插 USB，再拔 USB；看当前方式是否正确，恢复后重新写一笔。
4. 两端各导出诊断，确认能拿到两个文件。

下一阶段：下次签名到期时，用原文件夹覆盖更新，确认两端仍能打开、配对保留并连接。这项不能用第一天的安装成功代替。

这些需要本人操作和理解，不能由自动测试代替。其他应用按实际工作需要再验收，不必第一天跑完整开发者验收矩阵。

免费签名测试包与正式 Release 使用不同身份时，配对与设置不会自动迁移。保留旧测试 App，安装正式包后重新授权、配对；不要把复制配置、钥匙串或证书作为迁移步骤。详见[分发与 RC 流程](RELEASE.md)。

### Mac 离线截图

`engineering/scripts/render-rc-ui.swift` 直接渲染产品使用的 `MacMainView` 和 `MacMenuView`，只给现有 `MacModel` 注入固定状态。它不会启动协调器，不会读取钥匙串、请求 PadInk 系统权限、连接设备、启动屏幕录制链路或发送输入。图片只验证布局，不代表真实连接结果。

```sh

  -module-cache-path build/rc-ui/render-module-cache \
```

如果明确使用 SwiftPM `--build-system native`，Swift modules 在 `"$rc_ui_bin/Modules"`，需要以该目录替换 `-I`，并链接三个 target 的 `.build/*.o`。默认构建方式无需切换。

程序输出 Light / Dark 两套页面：首次打开、等待、USB、Wi-Fi、等待画面、恢复、错误、USB 配对、设置、帮助、诊断、关于和菜单栏。窗口内容尺寸覆盖 540 × 560、640 × 620、780 × 620 和 900 × 720；PNG 像素密度跟随 hosting view / 屏幕。`mac-screenshots.json` 标明每张图片的页面、尺寸、主题和 fixture 属性。

检查标题、设备名称、按钮和权限提示无截断；长状态在窄窗换行；主要连接动作可见；帮助、诊断和构建信息不挤占连接页。菜单栏须在小屏幕高度下仍可操作。

`NSHostingView.cacheDisplay` 对原生 sidebar 的选中材质存在离屏绘制限制：可能输出黑色选中背景或丢失选中标题。准确的原生窗口截图使用：

```sh

```

这个模式会短暂显示自己的 fixture 窗口，并以 `screencapture -l <windowNumber>` 仅截取该窗口。完成后关闭这些临时窗口，并恢复先前前台 App；仍不会启动设备连接。它可能需要运行环境的屏幕录制 / 截图权限。原生窗口截图已经确认 sidebar 的文字、SF Symbols 和选中材质正常。

### 最少真机验收

1. 两端首次打开：按屏幕提示授予 Mac 权限，USB 两端允许配对。看到画面后，在 Mac 应用先选笔，用 Pencil 画一笔；核对四角位置与工具栏可点击，界面入口无遮挡。
2. 在 GoodNotes 中连续双指滚动、捏合放大 / 缩小，再书写；打开并关闭 iPad 设置，重复一次，确认没有偏移、卡住的手势或焦点问题。

4. 两端切换 Light / Dark，在 iPad mini 或当前最小设备检查等待页和设置；Mac 缩到最小窗，检查长错误提示、权限与主要动作。

发布时只记录对应提交、实际验证范围和安装恢复所需材料。模拟器、离线截图、通过测试和成功构建都不能代替 Pencil、USB 与真实应用的验收。

## 5. USB + Pencil 输入性能定位与修复决策

真机问题边界：用户反馈插 USB 时，Mac 上实际笔迹也延迟、断续，LeafInk 和 Goodnotes 均出现，Mac 本地鼠标正常。这不能仅由 iPad 视频显示卡顿解释；本地鼠标正常也不能证明 tablet/Pencil 事件处理正常。先按实际路径 → 采集 → 发送/接收 → 注入 → 视频资源争用定位。Wi-Fi 断联单独立案，只有证据指向同一机制才合并。不得修改 LeafInk，不增加产品功能、不发布。

### 已核实的源码事实与测量缺口

- `USBMux.devices()` 只取 `ConnectionType == USB`；`USBDialer` 为 A/B 各开一个 usbmuxd Connect，iPad 接受 loopback 连接。这是 usbmux 隧道，不是凭插线推断的普通 IP 接口路由。仍需核对问题发生时的真实会话，不能把源码支持 USB 当作该次 USB 已生效的证据。
- Mac 的 `connectVideo` 将编码结果送到 `pnk2.mac.input`；`VideoSender.flush` 与 `Attachment.enqueue` 在该队列封装视频 payload/帧、调度发送。Pencil 接收解析和注入也在这个队列。
- iPad 的 USB `NWStream` 回调、`Attachment` 的 A/B 帧解析、`PadInputLink` 发送共用 `pnk2.pad.input`。`VideoDecodePump` 在帧解析之后才把工作送到媒体队列，因此独立解码队列不能消除解析前的争用。网络回调时间也不等于内核收到字节的时间。
- UIKit 采集 actual/coalesced 并保序，不发送 predicted；后台 mailbox 和发送队列有界。不过 mailbox 的捕获时刻在 UIKit 回调内，不能单独衡量回调之前的停顿。需分别看样本时间、回调时间与批大小。
- `input.receiveToInject` 在 `PencilInputPipeline.pencil` 执行 commands 之前记录；它不包含整个 batch 的 backend 执行和 CGEvent post 成本。backend 按批倒推事件 timestamp、连续 post；写入事件的 timestamp 不是实际投递时刻，保留时间字段间隔不等于实际均匀投递。
- 现有 Debug 详细诊断需要显式 `PADINK_DETAILED_DIAGNOSTICS=1`；普通导出删除 source/event 时间和 clock estimate，并将两端时间各自归零。不能对两个普通报告的时间直接相减。现有详细记录也缺少完整的逐包写完成、逐阶段排队和目标消费关联。

这些事实确定测量优先级，尚不证明主要瓶颈。当前没有与本次症状对应的完整双端 trace，不宣称已完成真机根因定位。

### 首轮诊断设计与观测边界

每次运行冻结双端 build、设备/系统、视频 profile 和应用版本。为 A/B 分别记录实际承载来源、连接实例、attachment UUID、generation、B epoch、认证成功/关闭/替换区间；USB 关联经脱敏的 DeviceID 与 Connect 结果，LAN 记录实际 NWPath。需要在同一复现区间证明 A/B 都是 USB，不能只看 UI 标签。由操作人配合关闭无线后的 USB 复现作为独立对照，不自动改系统网络设置。

每条样本以 attachment + generation + stroke + sample sequence 关联，另记 A/B 方向、wire frame sequence、batch 首尾序号和样本数。每个队列边界记录本机单调时间的 enqueue/start/end、队列深度/字节、最老年龄；记录拒绝、整笔取消、写失败、序号缺口、trace 丢弃/覆盖。TCP 字节流可能等待或断开；样本缺口不能未经定位就叫网络丢包，诊断丢记录也不能当作输入丢失。

| 段 | 必须记录与比较 |
|---|---|
| iPad 采集 | UITouch 样本时间、UIKit 回调进入/退出、callback ID、actual/coalesced 数、raw 到输出样本映射；核对 UITouch 与单调时钟基准及休眠恢复行为 |
| iPad 发送 | mailbox 入/出、发送队列入/出、stream send 调用/完成、in-flight 字节；send 完成仅代表本地完成语义，不代表 Mac 已收到 |
| Mac 接收 | stream callback、解帧完成、输入队列开始；分片帧保留首字节与完整帧时刻，多帧共回调不伪造独立到达时刻 |
| Mac 注入 | backend 开始/结束、每个 post 开始/返回、实际调用间隔、CGEvent timestamp、事件关联键；单独统计 terminal/reset/proximity-out |
| 系统/目标 | 可行时以只读 event tap 关联系统下游事件；受控测试接收器记录消费时刻。tap 观察不是目标应用消费确认；第三方应用只能结合 Mac 实际画面或其公开可用观测，缺失则标为未判定 |
| 争用 | 视频封包/解析/编码/解码/呈现耗时与队列等待、主线程停顿、共享锁等待、CPU/GPU/热状态；对齐同设备输入尖峰 |

计时热路径只写有界内存记录，异步导出，避免逐事件文件 I/O；保留诊断丢弃计数，做开启/关闭诊断的开销对照。无需增加逐笔内容采集；若扩展普通诊断，仅保留时间、计数与必要匿名关联，维持现有隐私边界。

同机直接计算阶段差值。跨设备保存多轮四时间戳 t1（本机发）、t2（对端收）、t3（对端发）、t4（本机收），估计对端减本机偏移 θ=((t2−t1)+(t3−t4))/2，网络往返估计为 (t4−t1)−(t3−t2)。转换到统一基准后才计算单程区间，并报告不确定度、估计年龄和漂移；链路不对称时不能声称精确单程值。换会话/休眠恢复重新估计。现有 `ClockEstimate.reliable` 的 25 ms 阈值不足以证明毫秒级精度；不确定度掩盖差异时仅报告本地分段与往返值，不用校时门控输入。

### 对照实验与归因门槛

先在正常视频下复现，再在诊断构建中保持同一 A/几何就绪状态，分别隔离 Mac 捕获编码、B 传输、iPad 解码呈现，最后恢复完整视频。不能直接断 B 后把重建/输入失去 ready 引发的变化当性能改善。每次只改一个因素，交替重复，记录各段 p50/p95/p99/max、最大事件间隔、batch 大小、取消数和序号完整性。

| 分类 | 支持归因的证据 |
|---|---|
| 到 Mac 前已延迟 | 样本→回调或 iPad 本地队列先出现尖峰；或校时误差允许分辨的发送→Mac 接收区间增大，而 Mac 接收后正常 |
| 到达及时、注入延迟 | Mac 接收正常，接收→队列执行或 backend/post 耗时增大，能对应具体排队工作或等待栈 |
| 注入及时、目标处理延迟 | post 与可观察系统下游节奏正常，但受控接收器/目标公开观测显示消费或绘制延后；只有 post 返回而无下游证据时仍不能排除系统分发 |
| 视频间接阻塞输入 | 输入尖峰对应视频工作/共享锁/调度等待，隔离该阶段可重复改善，恢复后可重复恶化；带宽未满不能反证 |

### 整体修复方向与范围决策

1. 先补观测缺口并复现，找出主导尾延迟的阶段，再定运行时改动范围；不通过增大 100 ms/250 ms 限制、丢实际点或延后抬笔来掩盖积压。
2. 若证实共队列阻塞，可重构为独立 A I/O/解析、Pencil 串行执行、B 封包/解析/媒体 worker；会话层仅保留短控制事务与不可变身份快照。跨队列 mailbox 必须有界，禁止视频大 payload 工作和同步等待进入输入关键路径，避免拆队列后新增逐样本无界任务。
3. 若采集先延迟，移走主线程重活，保留全部健康 actual/coalesced/terminal；若发送先延迟，修正写完成回调与队列调度/背压；若 backend 或系统下游先延迟，再评估投递模型和批处理。不能先假定固定频率重采样能解决问题。
4. 保留 attachment/generation/epoch 隔离、整笔过载取消、B 重建不取消 A、终点与安全释放；terminal 不得越过健康样本重排。对真实故障及时释放接触与 proximity，迟到工作不得复活旧笔。
5. 验证覆盖慢写、视频大帧/慢解析、慢注入、取消与重连竞态，再完成 USB 真机连续书写及目标应用橡皮工具擦除。建议每个目标应用至少三轮、每轮十分钟，包含长笔、短笔、快速抬落和写擦交替；要求无长卡顿、积压补画、健康笔序号缺口或抬笔残留，并确认尾延迟改善未靠大量取消换取。阈值是安全护栏，不是流畅性标准。自动测试与单独 Mac 回放不替代真实 Pencil 全链路验收。

实施顺序为诊断闭环 → 有证据的模块修复/重构 → 同条件复测。LeafInk 仅作为观察对象，不修改其源码或应用；没有目标消费观测时如实保留归因边界。

### 诊断构建与短时对照运行

Debug 构建使用 `SWIFT_OPTIMIZATION_LEVEL=-O`，通过启动环境 `PADINK_PERF=1` 开启元数据计时，默认关闭且 Release 强制禁用。无需同时开启含坐标的 `PADINK_DETAILED_DIAGNOSTICS`。两端 `PADINK_PERF_MODE` 使用相同值：`normal`、`no-video`（Mac 停采集/编码/视频发送）、`no-decode`（iPad 收完视频帧后不送解码）、`no-render`（继续解码但停止 Metal draw）、`low-video`（现有 30 fps / 50% USB 码率 profile）。它们是诊断启动开关，不是产品功能。B 心跳与 A 保留，不能把 no-video 称为完全没有网络 B 流量。

每轮重新启动两端，先正常实际呈现，5 秒预热后开始 45 秒窗口，结束后在两端 Documents 的 `PadInk Performance/` 自动生成现有格式诊断 JSON；`performance` 子对象含独立的原始本机单调时间，外层 support traces 仍遵守各自归零规则。导出仅在窗口结束后发生。环形记录最多 131072 条；导出竞争或覆盖数量不为零时，必须报告证据缺口。进程中间重连、B 重建、应用切换或没完成窗口的运行不能混作稳定对照。实验模式保持到下次启动；测完退出诊断进程并正常重开以恢复视频和关闭计时。

使用 `python3 engineering/scripts/analyze-pencil-performance.py <Mac.json> <iPad.json>` 输出同机阶段分布、队列深度、同笔事件间隔与跨设备区间。统计统一排除窗口前 2 秒，给停止捕获与 profile 切换留出收敛时间；仍需确认 `video.captureStopped` 和实际视频事件计数，不能只相信模式标签。跨设备估计使用邻近的前后四时间戳交换，并报告偏移跨度与估计年龄；漂移及非对称路径仍限制精度。不完整窗口拒绝统计，普通 support JSON 不可用于该配对计算。

已接入 UIKit 原始样本/回调、mailbox、发送队列、wire 帧关联、stream callback/owner queue/解帧、本地写完成/完成回调等待、Mac pipeline/backend/post、视频封包/队列/解码/实际呈现。Mac 可选只读 session event tap 在独立 run loop 观察下游；记录 `tapUnavailable` / `tapDisabled`，不主动申请新权限。tap 回调时刻包含观察线程调度，不能当目标应用消费。尚未直接测量内核 USB 排队、锁持有栈、GPU 调度或第三方应用消费；若分段证据指向这些位置，再使用系统 profiler 或目标已有公开诊断补足，不修改目标应用。

短时窗口用于定位，不替代长时书写验收。保持 VPN 与目标应用版本不变，正常 → 隔离 → 恢复正常交替重复；记录人看到的 Mac 原始笔迹和 iPad 镜像差异。诊断开启/关闭也需同条件对照，避免把计时本身的负担当作产品瓶颈。自动测试、统计脚本自测和构建成功都不代表真人卡顿已解决。

### 可选高画质视频

Mac「设置 › 视频画质」分别保存 USB / Wi-Fi 配置，下次连接生效。默认保留原 H.264、drawable 尺寸、码率公式与拥塞梯度。原生、4K、5K 选择不超过实际 Mac framebuffer；4K/5K 是长边预算，并保持宽高比。高码率支持倍数与自定义 Mbps，80/120/160/200 是实验点，不是上限。NV12 仍为 SDR 8-bit 4:2:0，不能称作无损色彩或 4:4:4。

扩展端用 `extendedVideo` 声明 payload 支持，H.264 High / HEVC Main 均要求硬件编码/解码。Mac 检查实际输出 subtype/尺寸，iPad 产生实际解码帧后确认；新模式 8 秒无确认或编码失败，在 B 上用更高视频世代回退原档位，不重置 A。旧端使用原配置。Wi-Fi 依据实际发送完成耗时、队列和 iPad 丢帧/积压反馈走原有降级迟滞；没有增加缓存容量。

支持诊断中的 `video` 保存实际 source/capture/encode/drawable/viewport、格式与硬件标志；`metrics` 包含采集/编码/解码/显示 FPS、窗口平均与滑动一秒峰值码率、窗口秒数和显示间隔分布。目标码率与这些实测值分开。静态画面、窗口切换和滚动应分开解释，未发生 Pencil 输入的窗口不得报告输入延迟为零。

同源帧硬件实验：`PADINK_VIDEO_MATRIX=1 PADINK_VIDEO_MATRIX_OUTPUT=/absolute/result.json swift test -c release --filter VideoQualityExperimentTests`。默认是合成小字、细线、笔迹形状与滚动样本，仅验证本机硬件回环，不能作为真机/Pencil 验收。可设 `PADINK_VIDEO_REFERENCE_FILE` 使用本次 2940×1912 NV12 参考帧；其他尺寸须调整试验读取器，不能误读尺寸。

双端 Debug 显式设置 `PADINK_VIDEO_REFERENCE=1` 后，每次进程只保存第 120 帧至本机 Documents/PadInk Video Reference；Mac 是编码输入，iPad 是相同 frameID 的实际解码输出。文件可能包含文稿画面，留在本机，正常运行和 Release 不保存。对比必须核对会话、frameID、尺寸；跨配置必须复用同一个源序列，不能把不同画面的 PSNR 差归因于码率。输入实验仍使用原有 `PADINK_PERF`，保留原始基线；视频测试不代表 Pencil 卡顿已解决。

日常视频模式为标准 8、高清 12、自动最高 16、高画质最高 20 Mbps，均保留原生采集并根据拥塞降级；新安装/未选择时仍使用原档位。H.264 为新日常配置初始编码，HEVC 可显式选择，仍需实际硬件解码确认。USB/Wi-Fi 独立保存，不迁移覆盖已有自定义配置；首次修改时保留此前配置以便恢复。80–200 Mbps 仅留在内部实验矩阵，不再作为普通 UI 选项。

低码率同源帧矩阵：`PADINK_VIDEO_MATRIX=1 PADINK_VIDEO_BUDGET=1 PADINK_VIDEO_MATRIX_OUTPUT=/tmp/padink-budget.json swift test -c release --filter VideoQualityExperimentTests`。`PADINK_VIDEO_REFERENCE_FILE` 可指定本机 2940×1912 NV12 源帧；实验本身不能代替 USB/Wi-Fi、真实 Pencil 或最终显示效果验收。
