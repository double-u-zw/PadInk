# PadInk 安装、升级与首次使用

PadInk 把 Mac 主屏显示到 iPad，让 Apple Pencil 和手指操作 Mac 应用。书写结果由 Mac 应用保存；PadInk 保存配对、设置和本机诊断。

## 当前正式渠道候选（0.3.0 / build 12）

2026-10-14：**0.3.0 / build 12** 已上传并完成 TestFlight 处理，Mac M 系列 arm64 包已通过 Developer ID 签名、公证和票据校验；尚未提交 App Store 审核或公开发布，维护者已安装并确认初步试用未发现问题，完整逐项验收仍待补齐。Mac 仅支持 M 系列，Intel 不再维护。build 10 是历史冻结工程资料，不是当前提交材料。下面的 Beta 3 / build 11 与 AltStore 步骤仅用于已有测试渠道，不是 App Store 安装要求。正式版 iPad 由 App Store 安装，发行前用 TestFlight；Mac 从维护者确认的 GitHub Release 单独下载 Developer ID 签名、公证的辅助端。精确下载链接尚待发布，不把旧未公证包当正式辅助端。

正式路径：使用与 iPad build 匹配的 M 系列 arm64 公证包；首次候选验收先解压到独立文件夹，保留现有日用安装，确认新身份可用后再考虑放入“应用程序”；打开 PadInk，允许屏幕录制、辅助功能，系统要求时退出重开。保持 VPN 开启。iPad 打开 PadInk 并解锁，插能传数据的 USB 线；系统询问时信任电脑，再在两端允许 PadInk 配对。预期不需 Xcode、AltServer、AltStore、开发者模式或每周续签，正式渠道的完整 USB 验收记录仍待补齐。不关闭 Gatekeeper，不用 root 或驱动。

保留现有个人测试安装。正式身份已确定为 com.padink.mac / com.padink.ipad，跨签名身份的设置与配对不能保证迁移；不要卸载、复制 Keychain 或先覆盖同名 Mac App。正式身份确认后独立安装验收，新版可用后再处理旧版。当前界面为简体中文，要求 macOS 14+ / iPadOS 17+，手写另需兼容 Pencil；第三方目标应用不包含在辅助端中。

本人 TestFlight 内部组“本人 USB 验证”采用手动分发，已加入 build12；本人随后已确认实际使用 TestFlight build12 与公证 Mac 包初步试用无问题。后续同渠道安装先在 iPad 接受邀请并安装 TestFlight 的 0.3.0 (12)，关闭开发者模式，退出 Mac 的 Xcode、AltServer 与旧 PadInk，VPN 保持开启，再运行独立文件夹中的正式 Mac 候选，完成下文 USB 文稿任务。没有外部设备验收记录。商店公开资料仍为本机草稿，当前 GitHub Beta 3 不等于 App Store 上架。

从 [Beta 3 发布页](https://github.com/double-u-zw/PadInk/releases/tag/v0.3.0-beta.3)下载 M 系列 arm64 完整 ZIP。先看包内“安装说明.txt”，装好后按[使用教程](使用教程.md)完成首份文稿，再填写[真人验收清单](试用验收清单.txt)。

Beta 3 发布时没有 Developer ID 公证包、TestFlight 或 App Store 下载入口；当前 build 12 的私有候选状态见首节。当前包的完整真人验收未完成。既有 Beta 2 源码采用 MIT；本次只公开安装包与用户文档，修复源码未发布。GitHub 自动生成的 Source code 附件仍是已有公开基线，安装请下载上述完整 ZIP。问题反馈见 [Issues](https://github.com/double-u-zw/PadInk/issues)。

## 免费安装与续签：AltStore Classic

先按简明说明安装 Mac 的 `PadInk-0.3.0-b11-mac-arm64.dmg`；它是未公证测试包，首次打开按系统提示处理。已有通过 Xcode 或其他账号/团队安装的同名 PadInk 时，先联系维护者确认恢复方式，不直接覆盖。

1. 从 [AltStore 官网](https://altstore.io/)下载稳定版 AltServer，放入 Mac“应用程序”并打开；macOS 27 使用 **1.8.1 或更新的稳定版**，旧首页链接可能仍返回 1.8，可在 AltServer 菜单检查更新。[官方 1.8.1 公告](https://bsky.app/profile/altstore.io/post/3mvqfomflhc26)说明已修复 machineID 错误。连接并解锁现有 iPad，按系统提示信任电脑、启用开发者模式。按[官方 Mac 安装指南](https://faq.altstore.io/altstore-classic/how-to-install-altstore-macos)安装 AltStore Classic；账号密码和双重认证只在官方窗口输入。
2. 已有 Xcode 开发签名的用户先确认账号证书：AltServer 为免费团队创建签名证书时可能撤销原证书，使已有开发 App 无法启动。优先使用未用于开发签名的免费账号；先确认现有开发 App 是否需要保留。无需另一台 iPad。
3. 将维护者提供的 `PadInk-AltStore.ipa` 传到 iPad“文件”，在 AltStore“ My Apps”点“+”选择 IPA。本次包显示为 **PadInk**。已有同 Apple ID 安装的 AltStore PadInk 时，按更新步骤导入，不先卸载旧 App。首次配对只确认正在使用的 Mac。
4. 在 AltStore 设置启用 Background Refresh，Mac AltServer 保持运行；可在 Mac“系统设置 › 通用 › 登录项与扩展”将 `/Applications/AltServer.app` 加入“登录时打开”。在 My Apps 的 Refresh All 手动验证续签，再打开同一 App 检查设置、配对和实际画面/输入。不要使用 Deactivate、卸载或换账号来处理失败。

免费账号通常最多同时安装 3 个侧载 App（含 AltStore），签名约 7 天。后台刷新由 iPadOS 调度，需要 AltServer 可达；插线本身不保证立刻刷新。Mac VPN 保持开启，若发现连接问题，检查 USB、设备解锁与 AltServer 发现链路，不要求关闭 VPN。[官方刷新说明](https://faq.altstore.io/altstore-classic/your-altstore)

已在 iPadOS 27.0.1 通过官方 AltServer 1.8.1 / AltStore Classic 2.3 安装独立版 PadInk，签名有效期确认为 7 天；Refresh All 原位续签后，到期时间延后，Bundle ID、Team、证书和源码摘要不变，测试文件内容一致、手指操作设置保留，无需重配对，USB 画面与 Pencil 正常。Mac VPN 全程保持连接，AltServer 已加入登录启动项。后台自动刷新、过期恢复和纯无 Xcode Mac 环境尚未实测，不能宣称“插线必定自动续签”；官方后台刷新也未验证能避让正在书写的会话。已有其他账号、团队或安装渠道的 PadInk 时，保留现有 App，先联系维护者确认迁移方式。

## 2. 安装步骤

1. 打开 M 系列 arm64 DMG，将 **PadInk.app** 拖到“应用程序”并打开。首次提示无法验证开发者时，按[简明安装说明](AltStore安装说明.txt)在系统设置确认，保留系统安全检查。
2. 安装官方 AltServer 与 AltStore Classic，将共用 `PadInk-AltStore.ipa` 保存到 iPad“文件”，在 AltStore 的 My Apps 点“+”导入。首次信任账号、启用开发者模式和后台刷新，见上节与简明说明。
3. 打开两端 PadInk，先使用 USB，按下节完成权限、配对和第一份文稿。

## 3. 首次运行：两端各做什么

| Mac | iPad |
|---|---|
| 打开 PadInk，点击菜单栏笔形图标；首次引导说明两端步骤 | 打开 PadInk，保持前台、屏幕解锁 |
| 按 PadInk 提示允许**屏幕录制**和**辅助功能**；按系统要求退出重开 | USB 插线并允许“信任此电脑”；首次确认 PadInk 配对 |
| 首次也确认 PadInk 配对，只允许正在使用的设备 | 等右上角显示 USB 和画面状态，再看到 Mac 画面 |
| 打开要操作的文稿，选择应用自己的笔或标注工具 | Pencil 书写；手指选工具，双指滚动或捏合 |

Mac 不需要主窗口。录屏授权后仍无画面时彻底退出重开 Mac PadInk；只关闭菜单不是退出。画面显示正常但不能输入时检查辅助功能授权。PowerPoint 缩放可能另询问“自动化”授权；拒绝时到系统设置的“隐私与安全性 › 自动化”调整，Pencil 书写不依赖这项权限。

先在 PowerPoint“绘图 › 笔”或 GoodNotes 笔工具写两笔，保存文稿，再确认结果。PadInk 不替你保存，也没有独立的 iPad 笔记本。

## 4. 连接、Wi-Fi 与恢复

Mac 面板和 iPad 右上角显示当前状态及 USB / Wi-Fi。连接建立与画面可以操作是两个步骤；“等待画面”先看 Mac 录屏提示，无需反复配对。

- 首次推荐 USB 配对。以后打开两端可自动连接；同一局域网、本地网络权限允许时，已配对设备也可用 Wi-Fi。
- 不插线配对：iPad“设置 › 连接与设备”中点“配对 Wi-Fi”；Mac 在“设置 › Wi-Fi 连接”中找到你的 iPad 并点“配对”。两端六位短码完全一致才允许。窗口约 120 秒，过期可重开。
- USB 优先：Wi-Fi 在线插线切到 USB；拔线尝试恢复 Wi-Fi。切换结束当前手势，恢复后重新落笔；断线期间的输入不会补送。
- Wi-Fi 找不到时检查同一网络、本地网络授权和 iPad 前台。访客、公司或课堂网络可能禁止设备互连，先用 USB。
- 恢复中先检查线和网络，保持 iPad 前台；持续失败先导出诊断再重开两端。主动暂停后在 Mac 点“重新连接”。

只有需要更换可信设备或明确修复配对失败时才“忘记设备”。普通断线、无画面和正常更新不需要删除配对。

## 5. 应用与输入范围

配套 Ecru 支持 PDF 文稿书写、双指连续缩放与二维平移；需维护者确认带 bridge v1 的适配构建，本包不包含 Ecru。PowerPoint 在绘图中选笔后写入；GoodNotes 在激活的文稿内容区书写、普通滚动和连续捏合。Preview 使用 PDF 自己的标注工具，需在实际 PDF 验证保存。Safari / Chrome 支持浏览、点击、滚动与页面缩放，网页不会自动变成可保存的手写笔记。

工具、颜色和橡皮通过目标应用的界面选择；输入作用于 Mac 当前应用。捏合与“恢复应用默认缩放”依赖该应用公开能力及当前文稿焦点。菜单或弹窗中先回到文稿；仍不可用就用应用自己的缩放控件。更多边界见[支持矩阵](SUPPORT_MATRIX.md)。

## 6. 升级与版本核对

先保存文稿、结束书写并退出 Mac PadInk，从同一次发布下载新包：用新的 Mac DMG 覆盖 PadInk，在 AltStore 用“+”导入新的 IPA。保持原 Apple ID，保留 App 与配对；**Refresh All 只续签当前代码，不会下载新版。**

更新后核对两端关于页面的版本 / build，并检查设置、配对、权限与真实操作。未公证 Mac 包更新可能重新询问权限或钥匙串访问；当前包的覆盖升级与授权延续尚待验收。

若旧 App 来自其他账号、团队或渠道，旧设置与配对不保证迁移，先保留已有 App 并联系维护者。正常同渠道更新无需卸载或复制钥匙串。出现版本不兼容时，更新为发布说明列出的双端组合并导出诊断；不要反复删除配对。

回退前先联系维护者，确认两端协议与设置格式兼容，不自行混装旧新包。

## 7. 出问题时：诊断与退出报告

| 问题 | 下一步 |
|---|---|
| Mac 没有菜单栏图标 | 从“应用程序”打开 PadInk；检查是否开了旧免费测试副本 |
| 等待连接 | 两端打开；USB 检查数据线、解锁与信任；Wi-Fi 检查同一网络与本地网络授权 |
| 已连接，等待画面 / 录屏失败 | 看 Mac 录屏权限提示；授权后按系统要求退出重开 |
| 画面正常，不能输入 | 检查辅助功能、目标文稿焦点及笔工具；仅手指失效时检查手指输入设置 |
| 配对未完成 | 核对短码，重新开启配对；不允许不一致的短码 |
| 恢复 / 解码失败 | 保持 iPad 前台；持续失败先导出诊断再重开 |
| AltStore 签名过期 / 刷新失败 | 保留 App 与错误信息，按简明安装说明检查 AltServer；联系维护者，不先卸载或换账号 |
| 两端版本不兼容 | 更新为同次发布列出的组合 |

Mac 打开 PadInk 主窗口的“诊断”，点“导出并在 Finder 显示”，取出“文稿 / PadInk 诊断”里的 JSON；iPad 打开“设置 › 诊断”，点“生成 iPad 诊断”，生成后用“分享诊断文件”保存到文件或 AirDrop。提供两端 JSON，附上**应用、USB/Wi-Fi、最后操作与发生时间**。Release 诊断没有画面、文稿名、窗口标题、完整文件路径或逐笔坐标；分享由你选择。[隐私说明](PRIVACY.md)

如果 App 突然退出，重开后可以导出诊断，但它不代替系统崩溃报告。Mac 在“控制台”App 的“崩溃报告”找到对应 PadInk `.ips`；iPad 在“设置 › 隐私与安全性 › 分析与改进 › 分析数据”查找 PadInk 对应时间的报告并分享。TestFlight 也可提交反馈。没有对应报告时直接提供时间和重开的诊断，无需猜测是 crash、系统结束还是内存回收。系统报告可能带设备或进程信息，发送前可查看。[Apple 控制台报告说明](https://support.apple.com/guide/console/cnsl664be99a/mac) · [Apple 获取 crash 报告说明](https://developer.apple.com/documentation/xcode/acquiring-crash-reports-and-diagnostic-logs)
