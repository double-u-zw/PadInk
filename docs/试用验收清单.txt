当前正式候选：0.3.0 / build 12，M 系列 arm64 公证 Mac + TestFlight iPad；先填写第八节正式渠道验收。已上传/公证不等于真人 USB 已通过，外部设备尚未验证。

双端关于页面和包内 VERSIONS.json 用于核对版本。

外部使用者按自己的实际包逐项填写：通过 / 失败 / 未测 / 不适用，并补充时间、现象与必要的诊断。维护者此前 RC1 的 USB 真人使用验收已完成，保留为已有基线；当前候选只补变化相关回归，不把已有 USB 结论重新归零。未记录的细项、独立首装及正式渠道仍单独记录。

二、首轮优先验收：独立安装与 USB 真实任务
[ ] U1 从零安装：只按安装说明完成双端安装、信任与开发者模式。
    判定：使用者不需 Xcode，能够打开两端；记录需要维护者额外解释的具体步骤与耗时。
[ ] U2 Mac 首次打开与权限：按系统流程打开未公证测试包，允许屏幕录制与辅助功能，退出重开。
    判定：可看到菜单栏入口与 iPad 画面，权限拒绝/缺失时有可理解的提示。
[ ] U3 首次 USB 配对：两端只允许本人设备，检查等待画面与可操作状态。
    判定：画面出现，工具点击与 Pencil 坐标正确，无需反复删除配对。
[ ] U4 真实文稿：选一份测试文稿，选笔、写长短笔、选颜色、擦除、滚动、缩放。
    判定：没有明显卡顿后补画、偏位、抬笔残留、误触或错误应用收到输入；PadInk 不替应用选笔保存。
[ ] U5 保存与重开：在目标应用保存，关闭文稿并重新打开。
    判定：书写/擦除结果按目标应用能力保留；记录具体应用、文件类型与操作。
[ ] U6 连续使用 30–60 分钟：写擦交替、快速抬落、长笔、滚动缩放交替；记录起止时间。
    判定：无崩溃、持续无画面、无法释放笔接触或明显积压补画；记录卡顿、发热、耗电及恢复方法。
[ ] U7 双端诊断：在两端找到版本、生成并保存 JSON。
    判定：试用者能够定位文件，核对本次包版本，知道可自行选择是否分享。

三、恢复、焦点与权限
[ ] R1 USB 拔插：先抬笔，再拔插；另在测试文稿中尝试书写时断线。
    判定：旧笔/手势安全结束，无残留按下；恢复后新笔可写，断线输入不补送。
[ ] R2 iPad 切到后台、锁屏后恢复；Mac 休眠再唤醒后恢复。
    判定：状态能解释等待原因，恢复后画面与坐标正确，不接续旧手势。
[ ] R3 切换目标应用/文稿、打开菜单或弹窗，再回到文稿。
    判定：输入作用于当前应用；缩放不可用时可理解，无旧缩放跑到新窗口。
[ ] R4 在系统设置拒绝/撤销权限，然后按提示重新授权。
    判定：录屏、辅助功能、本地网络及适用应用的自动化权限提示明确；重新授权后可恢复。
    只在测试设备及测试文稿操作；不在重要任务中撤销权限。
[ ] R5 配对管理（可选）：在专用测试环境忘记设备，再正常确认配对。
    判定：需要双方重新确认才能恢复；普通断线不需要“忘记设备”。

四、后续连接与应用范围测试
[ ] W1 同一局域网 Wi-Fi：已配对直连；有条件再从零六位短码配对。
    判定：短码一致才确认，画面/输入可用；记录网络环境，不把 USB 通过写成 Wi-Fi 通过。
[ ] W2 Wi-Fi → 插入 USB → 拔线恢复 Wi-Fi，至少三轮。
    判定：连接方式正确切换，旧手势结束，恢复后可操作且无需重配对。
[ ] W3 受限网络 / VPN（有条件）：保持原网络策略尝试连接，失败时退回 USB。
    判定：记录具体配置与结果，不承诺所有网络兼容，不要求关闭 VPN。
[ ] A1 PowerPoint：绘图笔、工具切换、滚动、公开缩放、保存重开。
[ ] A2 GoodNotes：激活文稿中的书写/擦除、普通滚动、连续捏合、保存重开。
[ ] A3 配套 Ecru：连续放大缩小、围绕文字捏合、移动中心、二维平移、写擦/套索与保存重开。
    仅匹配 bundle ID 且 bridge v1 的构建适用；本包不提供 Ecru。分别记 USB 与 Wi-Fi 结果。
[ ] A4 Preview：实际 PDF 的既有标注工具、保存重开、滚动和缩放。
[ ] A5 Safari / Chrome：实际页面点击、滚动、缩放；不检查网页手写保存。
    只填写实际安装并使用的应用；没装的记“不适用”，不要记“通过”。

五、续签与同身份更新（需后续时间或新包）
[ ] S1 手动续签：先保存文稿并结束书写；AltStore 用 Refresh All。
    判定：到期时间延后，App 身份、设置、配对保留，重开后 USB 画面与 Pencil 正常。
[ ] S2 后台刷新：记录是否启用、Mac/AltServer 是否可达、实际刷新时间。
    判定：以真实到期变化为准；观察对书写的影响，不把开关打开当作刷新成功。
[ ] S3 真实过期恢复：仅有条件在专用测试环境等待过期，保留 App 后按官方流程处理。
    判定：恢复后设置/配对仍在且能操作；别用修改系统时间替代，不主动破坏主设备安装。
[ ] S4 同身份覆盖更新：维护者提供下一 build 后，保留一个设置与配对，按说明更新双端。
    判定：两端新 build 正确，设置和配对保留；记录 Mac 是否重询 TCC/钥匙串，确认功能正常。
    首次转其他账号、团队或分发渠道另行验证，不当作同身份更新通过。
